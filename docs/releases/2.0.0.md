# NullGuard 2.0.0

Release version: **2.0.0** (2026-11-02).
The new language packs remain experimental and report-only in this release.

## Changes

NullGuard adds opt-in analysis of mixed repositories through optional Python,
ECMAScript (JavaScript, TypeScript, JSX and TSX), C#, Go and Rust language packs.
Projects are discovered and analyzed independently, with shared JSON schema 2.0,
HTML and SARIF reports and explicit coverage diagnostics. Partial or failed
analysis is distinguished from a complete scan.

Language packs are installed explicitly, verified with SHA-256 and the bundled
release signing key, and run with their own runtime dependencies. Scanning does
not download packs, restore application dependencies, import application modules,
or execute application tests and generators.

Dependency advisory matching supports offline exact-version input and optional
OSV queries. Java analysis also includes SpotBugs and FindSecBugs integration and
a dedicated SAST report page; compiled classes are required for those scanners.

## Compatibility and limitations

- Build and run the JVM distribution with Java 21.
- Signed language-pack targets are Windows x64, Linux x64 and macOS arm64.
- Existing positional Java commands and Maven/Gradle integrations retain their
  Java-only behavior and schema 1.0 output. Multi-language analysis is opt-in via
  `--languages=auto` or an explicit language selection.
- All six new languages remain experimental and report-only. Their findings do
  not have validated high-confidence status or general precision/recall claims.
- New packs do not provide stability grades, mandatory finding gates,
  cross-language call graphs, framework OpenAPI generation or advisory reachability.
- JSX/TSX source analysis does not establish React lifecycle correctness. Angular
  HTML templates are unsupported. C# support does not include other .NET languages.
- Missing packs, runtime failures and incomplete coverage must not be interpreted
  as a clean scan. See the [multi-language guide](../multilang/README.md) for
  runtime requirements, commands and exit statuses.

## Release evidence and further qualification

- 265 Maven tests passed, with one opt-in benchmark skipped; 16 script tests passed.
- Ten Gradle integration tests and signed Gradle publication staging passed.
- The [release JVM/Gradle workflow](https://github.com/techbhaskar/null-guard/actions/runs/41340944447)
  passed on Linux and Windows, including both Gradle versions and the benchmark.
- The [native language-pack matrix](https://github.com/techbhaskar/null-guard/actions/runs/41339793878)
  passed on Linux, Windows and macOS. Pack sources are unchanged from its tested
  commit `f34379814855d883d946349b1a101cb178cb7761`.
- All five signed Windows packs installed and removed through the production
  installer; the installed Python pack scanned the example successfully.
- Six packaged CLI/Maven entrypoint checks, OpenAPI fixtures, SARIF and schema 2.0
  validation passed. Aggregate coverage was 93.1% instructions, 79.8% branches
  and 85.13% fully covered lines, above the configured gates.
- Windows subprocess cleanup now tolerates temporary file locks, preserves
  persistent errors and interruption, and has deterministic regression coverage.

The Maven Central bundle contains all 13 components and 45 verified detached
signatures. Its CLI matches the GitHub distribution byte-for-byte.

`d927070f45021397f98fd1e04067270e952a67e8681750faab5d58a219b00af6`.
Central deployment: `a1072a4f-8ab3-45af-9491-4a94c1b4b4a1`.

The version 2.0.0 release does not promote the experimental packs to qualified
support. The following work remains necessary for that promotion:

1. Review the corrected analyzers' real-application findings against source.
   Historical baseline labels do not establish current accuracy.
2. Verify clean installation, mixed scans, behavioral tests and removal of the
   published signed assets on all three platforms. The published-release
   installation workflow runs this verification after publication.

See the [qualification record](../multilang/qualification/README.md) and
[publishing procedure](../publishing.md). Release availability must be confirmed
separately from analyzer qualification.
